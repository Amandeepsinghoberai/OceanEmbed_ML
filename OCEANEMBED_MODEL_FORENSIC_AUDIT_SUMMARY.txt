- SSS: processed_sss_arabian.nc

- Eddy vorticity: processed_vorticity_arabian.nc

- Cluster maps:
  - cluster_map.npy (Bay)

  - generated by K-means using mean SST/SSH plus latitude/longitude

5) INFERENCE PIPELINE
--------------------
Verified from live_predict.py:

User lat/lon
-> region classification
   - lon < 77.0 => Arabian Sea
   - lon >= 77.0 => Bay of Bengal
-> live data fetch using copernicusmarine.subset
   - SST
   - SSH
   - SSS
   - MLD
   - curl
-> feature construction
   - Bay: [sst, ssh, cluster one-hot]
   - Arabian: [sst, ssh, curl, mld, sss, vort, cluster one-hot]
-> normalization
   - load X_mean, X_std, y_mean, y_std from normalization_stats_*.npz
   - x_norm = (x - X_mean) / X_std
-> model inference
   - Bay: best_mlp_cluster.pt
   - Arabian: best_mlp_arabian_eddy.pt
-> inverse normalization
   - pred_temp = pred_norm * y_std + y_mean
-> bias correction
   - subtract per-depth correction from depth_bias_correction_*.csv
-> final profile
   - returns profile with depths_m and predicted_temp_c

6) REGION COVERAGE
------------------
Bay of Bengal model:
- Region defined by the Bay subset in build_dataset_cluster.py
- Latitude range: approximately 5 to 22
- Longitude range: approximately 80 to 100
- Used in live_predict.py when lon >= 77.0
- If cluster_id == -1, the function returns None

Arabian Sea model:
- Region defined by the Arabian subset in build_dataset_arabian.py and build_dataset_arabian_eddy.py
- Longitude cutoff: 77.0 is the key boundary used by the code
- Arabian Sea is used when lon < 77.0
- The full-region processed SST/SSH/GLORYS data covers a wider area (latitude 5 to 30, longitude 45 to 105), but the live inference and validation split for the Arabian model intentionally operate on the west-of-77 longitude slice

Important note:
- The code explicitly draws a hard boundary at longitude 77.0 between Bay of Bengal and Arabian Sea. This is not a learned boundary; it is an explicit region split in the code.

7) TRAINING DATA AND TARGET
--------------------------
Training inputs:
- Bay model: SST, SSH, cluster ID
- Arabian model: SST, SSH, curl, MLD, SSS, vorticity, cluster ID

Target used for training:
- GLORYS temperature interpolated to 15 fixed depths

GLORYS usage:
- Yes, GLORYS is used as the training target

ARGO usage:
- Yes, ARGO is used for validation against the trained model
- ARGO is not used as the target during training

Satellite data usage:
- Yes, SST and SSH are satellite-derived inputs
- Additional processed variables such as wind curl, MLD, SSS, and derived vorticity are also included in the Arabian pipeline

Temporal period:
- The full-region preprocess uses 2020-2023 data
- 4-year Bay processing uses 2020-2023 inputs
- The actual dataset building scripts split by date into train/val/test using chronological blocks:
  - train: first 75% of dates
  - val: next 13% of dates
  - test: final 12% of dates

Leakage risk:
- Time leakage risk is low because the split is time-ordered
- Spatial holdout is not evident from the code; no explicit location-based holdout is implemented

9) FISHERIES RELEVANCE
---------------------
This model can support:
- DIRECTLY SUPPORTED
  - full 0-1000 m temperature profile
  - depth-specific temperatures
  - surface-to-depth temperature structure
  - derived vertical gradients
  - thermal stratification indicators derived from the output profile

- POSSIBLE BUT NEEDS VALIDATION
  - thermocline location/strength estimation
  - subsurface thermal anomaly detection if a reference climatology is supplied

- NOT SUPPORTED
  - fish presence
  - fish species identification
  - abundance estimation
  - fish habitat labels
  - fishing-probability maps

Reason: the model is trained solely to predict GLORYS temperature at fixed depths. There is no fisheries target, species target, or biological dataset in the training pipeline.

15) SHORT CONCLUSION
--------------------
The project’s trained OceanEmbed model is a subsurface temperature-profile regressor, not a fish model. It uses surface and derived environmental features to predict GLORYS temperature across 15 fixed depths from 0 to 1000 m, with regional specialization for Bay of Bengal and Arabian Sea. It can support environmental interpretation for Fisheries Intelligence, but it cannot directly predict fish presence, abundance, species, or fishing probability without separate biological/fisheries data.
